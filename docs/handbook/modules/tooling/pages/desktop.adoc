= kUML Desktop
:description: The kUML Desktop app — editor with live preview, resizable split, mouse pan/zoom in the preview, simulation, workspaces and the optional local MCP server.

kUML Desktop is the native desktop app for kUML: a script editor with a live diagram preview, a
Knowledge Workspace viewer, state-machine simulation, an AI panel and an optional local MCP server.
It ships as a DMG (macOS), MSI (Windows) and DEB/RPM (Linux); see xref:ROOT:install.adoc[Installation].

== Layout: editor and preview

The view buttons in the status bar switch between three layouts: only the source, editor and
preview side by side, or only the diagram. In the side-by-side layout the divider between the two
panes can be moved:

* *Drag* the divider with the mouse. Each pane keeps at least 15 % of the width and 200 dp.
* *Arrow keys* move the focused divider (Shift for larger steps), *Home* and *End* jump to the limits.
* *Double-click* the divider, or press *Enter* while it is focused, to reset it to 50/50.

The position is saved when you release the mouse and restored on the next start.

== Knowledge Workspace: column widths

A Knowledge workspace shows three columns: the document tree, the Markdown editor and the diagram preview. Two dividers between them can be moved.

* The columns start at 20 % (tree), 40 % (editor) and 40 % (preview). The first divider sets the share of the tree; the second sets the editor's share of the area to the right of the tree. Moving the first divider therefore scales editor and preview together.
* Drag a divider with the mouse, or focus it and use the arrow keys (2 % per step, hold Shift for 10 %); Home and End jump to the limits.
* Double-click a divider, or press Enter on it, to return that divider to its starting position.
* The tree can take at most 40 % of the width, the editor at most 85 % of its area. Every column keeps at least 200 dp.
* In a window narrower than 616 dp the minimum widths cannot all be met; the columns then use the starting position 20 / 40 / 40. Your chosen widths are kept and apply again when the window grows.
* The widths are saved when you release the divider and restored the next time kUML Desktop starts.

== Moving and zooming the diagram

In the preview (and in the Knowledge Workspace viewer and the AI patch preview):

[cols="2,3"]
|===
| Gesture | Effect

| Drag with the left mouse button | Pan the diagram
| Mouse wheel or trackpad scroll | Pan (hold Shift to pan horizontally)
| Ctrl or Cmd + scroll | Zoom around the pointer
| Double-click, Home or Ctrl/Cmd+0 (preview focused) | Fit the diagram to the window
| Zoom buttons above the preview | Zoom in, zoom out, actual size (1:1), fit, center
| Actual size button | Show the diagram at 1:1, centered; stays 1:1 when the window is resized
| Center button | Center the diagram without changing the zoom
| Save as SVG / Save as PNG buttons (right of a separator after the zoom buttons) | Save the diagram that is currently shown, see <<Saving the shown diagram as an image>>
|===

Batik's own gestures keep working: Shift + drag pans, Ctrl + Shift + drag zooms, the arrow keys
move the diagram.

== Saving the shown diagram as an image

Two icon buttons at the right end of the zoom strip, *Save as SVG* and *Save as PNG*, save the diagram that is shown. The same
two actions exist as *File ▸ Export SVG* and *File ▸ Export PNG*; the buttons and the menu use one code path and always export
what is on screen:

* In the single-file editor that is the rendered diagram. While a simulation runs, the preview shows the diagram as it was when
  the simulation started, and that is what is saved.
* In a knowledge workspace it is the diagram of the selected document, including unsaved edits in the editor. A document
  without a diagram has nothing to save; the buttons and the menu items are then disabled (the tooltip says why) and never
  fall back to the diagram of another file.

Saving always goes through the file dialog; cancelling writes nothing, and a failure is reported in a message box. The
suggested file name is the document's name with `.svg` or `.png`.

The PNG is twice the diagram's natural width, between 800 and 4096 px (1600 px when the width cannot be read), on a white
background.

== Simulator: inspector, variables, payload, temporary guard editing

*Tools ▸ Simulate* runs a UML state machine or a SysML 2 state diagram against the diagram. Next to
the preview a side panel shows three collapsible sections: *Inspector*, *Variables* and *Trace*. Drag
the panel's left edge to resize it (280 to 520 dp; the width is not saved). *Tools ▸ Simulation
inspector* (or the panel button in the simulation bar) shows or hides the panel; hidden, only the
trace remains.

Actions without an implementation, such as `entry = "validate()"` or `effect = "notifyCustomer()"`,
are _abstract_: the simulator records them in the trace and carries on. Guards and assignments still
run in the sandbox, which accepts only its allowlisted functions (`log.*`, `math.*`, `str.*`, ...).

=== Inspector

The inspector lists the transitions that leave the active states, innermost state first, followed by
the transitions inherited from composite parents ("inherited from ..."). Each row shows the result of
its guard as a glyph and a word (`✓ true`, `✗ false`, `⚠ error: ...`), never by colour alone, and its
trigger or "(completion)".

* Click a row to highlight its transition in the diagram; click again to clear it. Send, Reset and
  scrubbing clear the highlight.
* *Not enabled* lists every event that cannot fire right now and why: no transition leaves the active
  states, every guard is false (with the values the guards read, "not set" for missing ones), or a guard
  could not be evaluated.
* Guards are evaluated off the UI thread against a frozen copy of the instance, through the same
  sandbox (time limit per guard) as a real step, and re-evaluated shortly after every change. They use
  the payload text currently in the event row (marked as a draft payload).

=== Variables

Every variable of the instance is shown with an editor for its type: a switch for booleans, a field for
numbers (decimal numbers, 64-bit integers; `NaN`, `Infinity` and similar are rejected) and a field for
text (at most 1000 characters). *Enter* or leaving the field applies, *Esc* discards, a bad value shows
an inline message and changes nothing. Lists, objects and `null` are shown read-only, as are variables
whose name the editor would not accept. Variables that guards read but nobody has set appear as
"not set" with a *Set* action that prefills the add row; *+ Add variable* creates new ones (names `[A-Za-z_][A-Za-z0-9_]*`, at
most 64 characters, at most 64 variables).

While you scrub the trace, variables are read-only and show their values as of that position; the
inspector then evaluates the guards with the current (possibly edited) guards, and says so. Sending an event from a scrub position forks the history there and the fork starts
with those variables. A position in the middle of a step shows the variables from the start of that
step, because changes made by effects are not part of the trace.

=== Event payload

*More...* in the simulation bar opens the free event row. Its payload field takes a JSON object whose
keys guards read as `event.<key>`. The payload is validated before anything is sent: at most 16 KiB,
at most 8 levels of nesting, a JSON object at the top level, and no top-level key named `name`, `id` or
`timestamp`. An invalid payload shows a message and disables *Send*; nothing is sent. *⌘+Enter* or
*Ctrl+Enter* in the payload field sends. The event buttons always send an empty payload.

=== Temporary guard editing

The pencil in an inspector row edits that guard with a syntax-highlighted, type-checked editor (at most
4096 characters). Editing a protected transition asks for confirmation first. An edited guard carries an
"edited" chip with the original struck through and a *Restore* button; a band above the list counts the
edits. Edits live only in the running simulation: *Reset* restores every guard, variable and the trace to
the script's state. While you scrub, guard editing is disabled.

=== What it does not do

* Nothing is written back to the script, and nothing goes to the clipboard.
* The diagram is not re-rendered: its labels keep showing the guards from the script.
* Lists and objects cannot be edited, only shown.
* The event buttons cannot carry a payload; use the event row.
* The panel width is not remembered between sessions.

== Validate

The Validate view gives the same findings as `kuml validate` (one shared `ValidationService`): structural
violations, note warnings and layout findings. Desktop evaluates the diagram's `layout { }` block for rendering and
validating, so a hint the diagram kind does not honour is reported in the view; see
xref:reference:layout.adoc[Layout].

== Exporting a workspace as PDF

With a knowledge workspace open, *File ▸ Export Workspace ▸ As PDF...* exports it as a handbook, one PDF per document or a
diagram folio; see xref:workspace-pdf-export.adoc[Workspace PDF export].

=== Exporting a single document

The document header of the knowledge workspace has a *PDF* icon at its right end (tooltip: _Export this document as PDF_).
It opens the same dialog with the scope already set to *Current document* and the _per document_ kind, without a cover page.
The scope row of the dialog always offers *Current document (path)*; it is disabled when no document is open. Opening the
dialog from the *File* menu keeps the whole workspace as the scope.

The PDF is built from the files on disk. If the document has unsaved edits, the dialog says so; save it first.

=== The dialog's status area

All messages of the dialog appear in a fixed status area above the buttons, so the options never move: the
check progress, the result, an overwrite question and any warning. When a diagram stays too small to read, the area
lists a few affected diagrams and offers *Export anyway*. *Use A3 landscape* is offered only with a fixed page size
(a page that is not already A3 landscape); clicking it switches the page settings to A3 landscape and checks the
workspace again, it does not export on its own. With the automatic page size there is no such button; the area
suggests lowering the minimum scale under *Advanced* instead.

== About dialog

*Help ▸ About kUML…* shows the product name, a one-line description, the copyright, and two links (the kUML website and the Apache License 2.0 text), which open in the default browser. If the platform has no browser support, the address is shown as selectable text instead of a link.

The dialog lists three facts: the version, the build date (the commit date of the build, `unknown` when the build was made outside a git checkout) and the Java version the app runs on. *Copy version info* puts exactly these three displayed lines on the clipboard, which is handy for bug reports.

*Open-source licenses* shows the bundled NOTICE plus the license texts of the bundled fonts (Inter and JetBrains Mono, SIL Open Font License 1.1).

== Local MCP server

Desktop can host an optional, local MCP server so an AI agent works on the script that is open in
the app; see xref:reference:authoring-mcp.adoc#_driving_kuml_desktop_over_mcp[Driving kUML Desktop over MCP].
It is off by default. With a knowledge workspace open, the agent can also list, read, write, validate
and render the workspace's documents; if a file changes on disk while you have unsaved edits, the editor
shows a banner to reload or keep your version.
