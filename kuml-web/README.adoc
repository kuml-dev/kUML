= kuml-web
:description: Ktor/Netty HTTP server with live SVG preview for kUML scripts

`kuml-web` is the browser-based live-preview module for kUML.
It provides a single-page web application with a CodeMirror 6 editor,
real-time SVG rendering, theme/layout selection, and SVG/PNG download.

== Quick Start

[source,bash]
----
# Start via the kuml CLI (recommended)
kuml serve

# Or run directly via Gradle
./gradlew :kuml-web:run

# Custom port
kuml serve --port 9090
----

Then open http://localhost:8080 in your browser.

== API Endpoints

[cols="1,1,3"]
|===
| Method | Path | Description

| `POST`
| `/api/render`
| Render a kUML script to SVG or PNG. Body: `RenderRequest` JSON.

| `GET`
| `/api/themes`
| List all available theme names.

| `GET`
| `/api/examples`
| List bundled example scripts (name + title).

| `GET`
| `/api/examples/{name}`
| Fetch source of a named example script.

| `GET`
| `/api/health`
| Server health check. Returns `{"status":"ok","version":"..."}`.

| `GET`
| `/`
| Single-page web application (HTML + CSS + JS).
|===

=== POST /api/render

Request body:

[source,json]
----
{
  "script": "classDiagram(name = \"Example\") { classOf(name = \"Foo\") }",
  "format": "svg",
  "theme": null,
  "layout": "auto",
  "widthPx": 1024
}
----

Response body:

[source,json]
----
{
  "ok": true,
  "format": "svg",
  "svg": "<svg ...>...</svg>",
  "pngBase64": null,
  "durationMs": 42,
  "error": null
}
----

`format` may be `"svg"` (default), `"png"` or `"latex"`. For PNG, the response contains `pngBase64` (Base64-encoded PNG bytes); for LaTeX, the TikZ source is in the `latex` field (see <<web-output-formats>>).

[[web-output-formats]]
== Web playground output formats

The playground and `POST /api/render` produce `svg`, `png` and `latex`. LaTeX output is generated by the same renderers and refusal rules as `kuml render --format latex` (shared in `LatexExportSupport`), so the web output and the CLI output cannot drift apart.

.LaTeX support per diagram family
[cols="2,1,3",options="header"]
|===
| Family | LaTeX | Note

| UML, C4, Service Blueprint | yes | Blueprint needs no layout and uses no theme.
| SysML 2 (BDD, IBD, UC, Req, STM, Act, Seq, Par) | yes | Package diagrams: no.
| BPMN process and collaboration | yes | Choreography and conversation diagrams: no.
| ERM Martin, Bachman, IDEF1X | yes | Chen: no.
|===

Behaviour:

* A family without LaTeX output answers `format = "latex"` with HTTP 422 and the CLI's message in `error`.
* An SVG response additionally carries `latexSupported` (`true` or `false`) and, when `false`, `latexUnsupportedReason`. The playground uses them to disable the LaTeX button and to show the reason as a muted hint, instead of failing on click. PNG, LaTeX and error responses leave both fields `null`.
* `standaloneTex = true` returns a complete `\documentclass{standalone}` document instead of a bare `tikzpicture`. In the playground the checkbox is labelled "Standalone document".
* The optional `notation` field (`martin`, `bachman`, `chen`, `idef1x`) overrides the ERM notation declared in the script; the effective notation decides whether LaTeX is available. The playground has no notation selector, only the API field.
* The LaTeX source is delivered as the JSON field `latex` (`application/json`, no `Content-Disposition`). The playground turns it into a `diagram.tex` download (`text/x-tex;charset=utf-8`) in the browser.
* The server does not compile TeX (no `pdflatex`), and no format has a response size limit or render timeout of its own.

== Build

NOTE: Building and running `kuml-web` with Gradle needs Node.js (`^20.19` or `>=22.12`) with npm. The editor
frontend is bundled with Vite during `processResources` (`npm ci`; network access on the first build). See
`DEVELOPMENT.adoc` for details.

[source,bash]
----
# Compile only
./gradlew :kuml-web:compileKotlin

# Run all tests
./gradlew :kuml-web:test

# Build runnable distribution
./gradlew :kuml-web:installDist
----

== Configuration

[cols="1,1,3"]
|===
| Option | Default | Description

| `--port`
| `8080`
| HTTP port the server listens on.

| `--host`
| `0.0.0.0`
| Host/interface to bind to. Use `127.0.0.1` for localhost-only access.
|===
